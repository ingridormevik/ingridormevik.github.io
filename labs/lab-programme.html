TECHNIQUE 01 / Structure and style

Change the atmosphere

A paragraph says “The forest remembers.” You change its CSS colour. What should happen?

p { color: #b9ef86; }
1. Make a prediction

JavaScript is needed for the interactive feedback. The explanation is also available below.

2. Test the example

The forest remembers.

Example not run yet.

Why it works

CSS changes presentation. The paragraph’s words belong to the HTML. You can express a mood through styling while keeping the text the same.

Need a hint?

Separate what the page says from how it looks.

Optional extra challenge

Give the same sentence two contrasting moods using only CSS. Ask a partner what each version suggests.

Something is not working?

No visible change? Save the CSS file. Check that index.html links to that file and that your selector matches the element.

Opening words you can use
Hi, I’m Ingrid, your lab assistant and a third-year Digital Culture student. My knowledge is still compiling. I do not know everything, but I am good at finding things out, and I am here to help you do that too. I work across electronic literature, games, research, activism and Mount Media. Live demonstration: click-by-click teaching checklist
  1. Open the chosen public page. In Chrome, right-click a heading and choose Inspect. Point to the selected element in Elements and its CSS in Styles. Explain that these are the current page elements; View page source shows the delivered HTML and may differ after JavaScript runs.
  2. Use the simple starter page to read the structure from the top: doctype, html, head, title, body, heading, paragraph, details and summary. Name structure, visual styling and behaviour as different layers; HTML itself can provide a reveal interaction.
  3. In VS Code choose File → Open Folder and open a memorable Desktop folder. Open index.html. Show one text edit, Save, and Show Preview.
  4. Create style.css beside index.html. Add the supplied stylesheet link inside head. Paste the small CSS example, save both files and show the effect.
  5. Change one spacing or colour value and explain its purpose. Ask students to predict the effect before you save.
Support, recovery and differentiation
  • If Live Preview fails, check the folder and file extension; use the downloaded starter in the same folder and open index.html locally for this simple exercise.
  • If CSS does nothing, compare the link's filename with style.css and save both files.
  • If someone is already confident, ask for a meaningful second version rather than more decorative effects.
  • If installation is blocked, pair for the demonstration, let the student write their own content and file plan, and agree any completion arrangement with the course lead; do not invent an exemption.

TECHNIQUE 02 / Events and state

Make the page respond

This button runs the same line each time. What happens on the second click?

story.textContent = "You belong here.";
1. Make a prediction

JavaScript is needed for the interactive feedback. The explanation is also available below.

2. Test the example

Who gets to belong?

Example not run yet.

Why it works

Assignment sets the text to the given value every time. A toggle needs a rule that checks the current state and chooses a different value.

Need a hint?

There is no “otherwise” branch in this line.

Optional extra challenge

Make a button alternate between two messages. Explain the condition that chooses the next message.

Something is not working?

Nothing happens? Check the element’s ID, when the script loads, and the browser console. Confirm that the click listener is attached to the intended button.

3. Use it in your own project

Try your own interaction twice. Describe its starting state, the input and the resulting state. Decide whether a repeated click should repeat, toggle or advance.

Live demonstration: click-by-click teaching checklist
  1. Open a published example while signed out. Copy the playable URL, not the repository's file view or a local localhost address. Test one complete interaction.
  2. For a webpage, follow the GitHub guide: create the practice repository, upload the folder's contents with index.html at the top level, merge the proposed change, and configure Pages. Explain that publication can take time.
  3. For Construct, show Menu → Project → Export and the web/HTML5 export route described in the official guide. Keep the complete exported output together. A .c3p is an editable project, not a playable web upload. Use the course's agreed hosting route for larger exports.
  4. Show how a filename case mismatch breaks an asset after upload. Repair it and retest. Explain that students should not upload personal files or unrelated Desktop contents.
  5. Open Chicago's author-date examples. Match one source's actual author or organisation, date, title and URL to the appropriate example. Show the relationship between an in-text citation and its reference-list entry.
Support, recovery and differentiation
  • For a 404 page, check index.html, the publishing branch/folder and deployment status. For missing images, check relative paths and filename case.
  • If the browser upload cannot handle a Construct export, keep the complete export and follow the course's approved hosting method instead of uploading incomplete pieces.
  • If accounts or publication are blocked, complete the test and documentation locally, record the precise issue and agree the remedy; do not mark the official sharing requirement as completed.
  • Do not generate a student's reflective essay. Discuss a decision and ask them to write their own analysis.

TEACHING THE SAME LAB TWICE

Reset the example. Keep the learning goal.

  1. Before the morning: arrive early enough to test projector, network, guides, starter files and the actual MittUiB task. Show the QR. Confirm which duration fits the room booking.
  2. During either group: use a help queue, finish one debugging conversation at a time, and pause the room for a 60-second repair if several students hit the same issue.
  3. At the end: protect the upload block. Check submission confirmation, save the demonstration and write three anonymous notes: common blocker, useful explanation, pacing change.
  4. Between groups: keep a separate afternoon demo copy. Restore the clean starter, close student work and reset any sample choices. Test the links again.
  5. For the afternoon: teach the same outcome and completion evidence. Use the morning's findings to improve explanations. Afternoon students are a new group, not a continuation of the morning class.
  6. After both: note what needs follow-up through the course's agreed process. Keep necessary teaching records in the course's approved systems.

Suggested help order: cannot open → cannot run → cannot save/submit → cannot explain → ready to extend. Avoid turning one student's computer into a long private lecture.
