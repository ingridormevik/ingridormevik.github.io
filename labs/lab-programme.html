The two files are joined by one line in the <head> of index.html: <link rel="stylesheet" href="style.css">. Think of it as the cable between them. If the file name or folder is wrong, the page loses its style.

02 / READ ONE RULE

Every CSS rule has the same shape.

This is a real line from your starter. Click each part to see what it does.

:

Selector: body chooses which HTML to style. body means the whole visible page. h1 would mean only your heading, p every paragraph.

Braces { } hold all the instructions for that selector.

Property is what you change: color is the text colour, background is the colour behind it.

Value is how it changes. #f3f0e8 is a warm off-white.

Semicolon ; ends one instruction. Forgetting it is the most common reason CSS silently stops working.

HOW TO READ A HEX CODE

#f3f0e8

A hex code is three pairs: red, green, blue. Each pair goes from 00 (none) to ff (full). #ff0000 is pure red, #000000 black, #ffffff white. #f3f0e8 has almost full red, green and blue, with a little less blue, which is why it feels warm, like paper.

03 / WHY COLOUR SPEAKS

On screens, colour is a language we already know.

You have spent years learning what interface colours mean, without anyone teaching you. Designers use that shared knowledge on purpose. So can you.

Red badge

Notifications, errors, live. Red asks for your attention now. Apps use it because it pulls you back in: colour as part of the attention economy.

Link blue

Early web browsers made links blue, and we still read blue as “click me”. Banks and social platforms lean on blue to look calm and trustworthy.

Dark mode

Night, privacy, a phone in bed. Dark screens feel intimate and late. They can also feel like a terminal, a hacker, a secret.

Soft pastel

The “aesthetic” feed. Pastels signal a mood, an identity and a community. Choosing a palette online is often choosing who you belong with.

Meaning is cultural, not universal. White can mean a wedding in one place and mourning in another. Green can mean nature, money, “go” or a political party. Ask: who is reading this, and what have they learned?

Contrast decides who is included. If text and background are too close, people with low vision, tired eyes or a bright screen outside cannot read your page. Aim for a contrast ratio of at least 4.5 : 1, and never let colour be the only way something is explained.

06 / DO IT IN VS CODE

Now make the change for real.

  1. Go back to style.css in VS Code.
  2. Inside body { }, replace the value after color: and after background: with your two hex codes. Keep the # and the ;.
  3. Below the body rule, write your first rule of your own. Give only the heading its own colour:
    h1 {
  color: #b3122e;
}
  4. Save with Ctrl + S (Mac: Cmd + S). Live Preview updates on its own.
  5. Before you look at the preview, say out loud what you expect to change. Then check.
Nothing changed?
  • Not saved. A dot on the file tab in VS Code means unsaved changes. Press Ctrl/Cmd + S.
  • Missing # or wrong length. A hex code is # plus exactly six characters: #b3122e.
  • Missing ; or }. One missing character can stop the rest of the file. VS Code underlines it in red.
  • Wrong folder. style.css must sit next to index.html, and the <link> line must say href="style.css".

AFTER THE GUEST LECTURE / AI & CODE

AI can write the code.
You make the decisions.

The guest lecture and performance on coding with AI is your food for thought today. In this lab we look at AI coding together: what it produces, what it decides without being asked, and what you choose to keep.

  1. Intention first. Before you ask anything, write one sentence: “When someone clicks ___, the page should ___ because ___.” That sentence belongs to you.
  2. Ask for one small thing. Ask an AI assistant for that single interaction in your project. Not the whole page, just one response to one action.
  3. Read before you paste. Go through the answer line by line. Mark what you understand, what you do not, and what it decided without being asked: colours, fonts, text, extra features.
  4. Break it and make it yours. Change at least one thing by hand: simplify it, rename it, reject a decision, fix what does not work. Then test it twice.
  5. Log it. In your experiment note, write which tool you used, what you asked, what you kept and what you changed. Follow the course’s rules for declaring AI help in assessed work.

Your choice: you can do this whole lab without AI. Write the interaction yourself and compare it with a classmate who used AI. That is an equally good experiment.

If AI wrote half the code but you made the decisions, who made the page?

LAB 2 / OPTIONAL 10-MINUTE GROUP VERSION

Use an explanation as a claim to test.

AI coding is part of Lab 2, as Alinta announced. This is the short small-group version inside own-project time; the full walkthrough is the AI coding tutorial. Students who choose it predict the same short program, explain it, test a claim and record the source of help. Students can decline AI without having to defend that choice. It does not change what the course brief allows for AI in the final assessment.

  1. 2 minutes: predict what the supplied code does before asking for help.
  2. 3 minutes: read the relevant documentation with a peer, or use the explanation prompt below if approved.
  3. 3 minutes: check one claim against the running example and an official reference.
  4. 2 minutes: explain the code in your own words and record what helped, what was uncertain and what you verified.

This ten-minute comparison is an optional small-group activity within Lab 2's own-project time, not another whole-class task.

Explain this short JavaScript snippet line by line for a beginner. Do not rewrite it or add features. State what must already exist in the HTML. Suggest one prediction I can test in the browser, and identify anything you are uncertain about.

Use only the small supplied practice snippet. Discuss understanding, responsibility, credit and the choice not to use AI. Keep tool names, dates and the help received in the process log; use the course's disclosure rules for assessed work.

Practice and assessment

Practice and assessment are different.

Each lab reserves time for the completion screenshot described in the supplied teaching summary. The actual MittUiB task determines the required evidence. Do not infer a new attendance threshold, alternative compulsory submission or final deadline from this programme.

The earlier supplied assessment brief describes an interactive work about speculative digital futures, an independently written document of 2,000 words ±10% with a working URL and analysis of theme, genre and process, plus a video walkthrough. It also restricts AI in making the work and prohibits AI-generated written analysis. Confirm the current autumn brief and Alinta's explanation before using those details as assessment instructions. The newer teaching summary calls for Chicago author-date referencing; use the current course guidance and official examples.

Personal experience is an artistic resource, not a requirement to disclose intimate material. Students can use ordinary observations, fictionalise details and choose what remains private. All core activities here work without generative AI.
